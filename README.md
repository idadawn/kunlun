# Kunlun（昆仑）· 绿麒麟水站会员管理系统

> **绿麒麟水站｜小分子团弱碱活性水** —— *鲜活每一滴，好水到你家*

基于 [Qian](https://github.com/idadawn/qian) 平台插件规范与 [Kun](https://github.com/idadawn/kun)（.NET 10 云原生框架）构建的水站数字化会员管理系统，采用 **Monorepo** 架构组织后端服务、共享领域模型、管理端 PC 与员工/会员手机 H5。

## 业务入口

- 管理后台 `/admin`：管理员登录后办理会员、订单、账务与设置。
- Windows 管理端：门店电脑（Windows 10 / 11，64 位）安装后在独立窗口打开正式环境的管理后台，页面随线上发布自动更新，默认自动登录（在本机记住密码），见 [Windows 管理端说明](apps/windows-admin/README.md)。
- 员工工作台 `/staff`：独立员工登录入口，适配手机。首页、底部导航和能办理的业务按角色开通的功能显示，管理员在管理端「系统设置 → 移动端配置」设置并在手机框里实时预览。
- Android 员工端：将员工页面打包进 APK，以内置 WebView 运行，见 [Android 构建与模拟器安装](apps/android-staff/README.md)。
- iOS 员工端：同样把员工页面打包进 App，由 WKWebView 运行、原生转发接口，支持 iOS 17+，见 [iOS 员工端说明](apps/ios-staff/README.md)。
- Android H5 应用：安装后可切换会员和员工登录入口，见 [Android H5 打包说明](docs/android-app.md)。
- 会员中心 `/member`：会员登录后只读查看本人水票、用水与充值记录、押金和桶袋；下单、充值、交退押金都到店或找送水员办理。
- iOS 会员客户端：SwiftUI 原生水票、记录、押金与账户页面，支持 iOS 17+，见 [iOS 开发与验证说明](apps/ios-member/README.md)。
- Android 会员端：把会员页面打包进 APK，以内置 WebView 运行，只放行会员页面，支持 Android 8.0+，见 [Android 会员端说明](apps/android-member/README.md)。

根入口跳转管理后台。员工和会员可在手机浏览器打开对应的 H5 入口。

## 本地启动与验收

先显式设置 `ConnectionStrings__Kunlun`、`Kunlun__Jwt__SigningKey`，以及首次初始化所需的 `Kunlun__Bootstrap__Username` / `Kunlun__Bootstrap__Password`（见 `.env.example`）；Android App 检查更新另需蒲公英账号 API Key `Kunlun__Pgyer__ApiKey`，不设置时一律答没有更新。应用不自动读取 `.env.local`，默认不创建演示账号。已有员工的用户名为原工号；会员登录账号在管理端会员详情中设置。

```sh
dotnet run --project services/Kunlun.WaterStation --urls http://127.0.0.1:5188
pnpm --filter @kunlun/admin-pc dev   # http://127.0.0.1:5173/admin
pnpm --filter @kunlun/mobile-h5 dev   # http://127.0.0.1:5174/member 与 /staff
```

两个开发服务器都把 `/api` 代理到后端，功能页采用 `/admin/plans`、`/member/records` 等路径，支持直接访问和刷新；`.html` 地址一律返回 404。`pnpm build` 先做 TypeScript 检查再构建，产物部署方式见 `deploy/nginx.conf`。

后端验收必须显式设置 `KUNLUN_TEST_DATABASE_URL`（数据库名包含 `test`，账号需有创建测试库权限），再运行 `dotnet test Kunlun.slnx`。测试自行创建、销毁独立数据库，不使用业务库。


## 已接通业务

- 三端用户名密码登录、会员账号设置、员工账号管理、修改密码与退出失效。
- 水品新增时同时填写配套桶/袋类型、容量和押金单价；每种水品独立管理桶袋库存、押金、领还和报废，即使同为桶装水也不能混用。容量和容器类型固定，换规格需新增水品。加错且没有套餐、单据或库存记录的水品可删除；各水品分别建充值套餐、记自提/配送水票。默认两种水品（袋装 5L、桶装 15L）各有 100 / 499 元套餐，后台可编辑，历史充值保留原价快照。
- 水票按充值批次预占、核销、取消释放；管理员按原价退清剩余付费票并回收赠票。
- 补录老会员上系统前的数据（「补录会员上系统前的数据」权限，默认只给管理员）：在会员档案点「补录历史数据」，记下买的什么套餐、还剩多少、交过的押金和手里的桶袋，每次生成一张补录单可追溯。补录的不算当天收入；知道套餐的余量能按原价退，套餐不清楚的只记张数；没用过、没退过时还能改。
- 门店点单（员工端、管理端）：选水品加入购物袋后选择送水上门或到店取水；顾客在店取水时当场交付、登记换回空桶并收取需补押金。交付时押金写清手里几个、本次领几个、应付多少（欠的 + 本次的），先问客户是否支付押金（是就带出应付、可往下调，否就记欠押金），再问有没有损坏的桶袋（不赔付要写原因），都记进水单的交付备注；门店下单时不知道会收回几个空桶，需补押金 = 欠的 + 这次领的，送达时每收回一个空桶少交一个。确认交付按水单的水品写清是桶还是袋（5L 袋装水写“满袋领出 / 空袋收回”，押金按水袋算）。会员端只读，不能自助下单。
- 费用支出（管理端「财务管理 → 费用支出」）：登记买桶袋、配件耗材、维修和其他支出，可补登以前的日期，记错了写明原因作废；登记买桶袋时选买的哪种桶袋，买的个数同时加到店里库存，袋桶库存和袋桶台账都记一笔「新购」（已经在袋桶库存登记过的选「只记钱」）；反过来袋桶库存「新购」时填了花费，同时记一笔「买桶袋」支出，两边互带单号。支出进经营汇总（`expenseTotal`）、本月收支和导出。
- 会员收货地址簿：每位会员可保存多个地址（收货地址、门牌号、联系人、手机号），由店员维护，联系人和手机号默认带出本人；配送下单从地址簿选择并保存地址快照。
- 员工账号可停用或删除（不能删除自己和最后一个管理员）。
- 会员可停用或删除（「停用和删除会员」权限，默认只给管理员，在会员列表每一行的「操作」里办理，已停用会员的档案页头也能重新启用）：停用要写原因，停用后会员端登录不了、员工也办不了这位会员的业务，水票、押金和桶袋原样留着，可重新启用；没完成的水单、待审核的赠送、收押金、退款和损坏不赔付、待确认的报废要先办完。只有一条记录都没有的会员（建错、重复的档案）能删除。
- 管理端、员工端与会员端共用同一 PostgreSQL 数据。系统不接入任何在线支付：水费和押金都由店员线下收款后登记。


管理端侧边菜单按管理工作分组：经营总览；日常业务（水单管理、会员管理）；财务管理（水费充值、押金管理，分别汇总、筛选和导出，押金金额不计入水费；审核，充值时手动赠送的水票、店员办理的退押金和退水费、员工收的押金、交付时损坏桶袋不赔付要不要管理员审核，由该页四个开关决定，默认都要审核；赠送、收押金和损坏不赔付不分谁办的（管理员账号也一样）都要在这里批准，收的押金待审核时交付照常算进押金覆盖，管理员核对到账批准后才入账，驳回就作废、会员变成欠押金；费用支出，买桶袋、配件耗材、维修等花出去的钱一笔一条，作废不删除，按时间统计支出、同期水费净收和结余）；袋桶管理（袋桶库存、袋桶台账）；商品管理（水品与押金标准、充值套餐）；系统设置（员工账号、移动端配置）。经营总览另有「本月收支」：本月水费净收 − 本月费用支出 = 结余。

「移动端配置」按角色（店员、送水员、管理员）开通员工手机端功能并排序，右侧手机框用员工端同一个首页组件实时预览。店员、送水员开通哪些功能就拥有对应权限，保存后已登录员工下一次操作即生效；管理员后台权限不变。员工端新增「袋桶库存」页和「今日经营」首页卡片，均需单独开通。待处理水单、待审核的赠送、收押金、退款和损坏不赔付、待确认报废和店里桶袋偏少以菜单角标提示。充值套餐页可根据当前启用配置生成高清价目表 PNG；运行 `pnpm test:poster` 检查导出数据与门店价目表一致。


`packages/shared/src/routes.ts` 是三端路由清单，React Router、开发/预览服务器和 Nginx 配置都以它为准。`pnpm test:web` 验证路由表、Nginx 规则、开发与构建预览，`pnpm check:pages` 检查构建产物。充值表单使用分类套餐弹窗（按水品和领取方式分类），只可选择启用套餐。


桶和袋均按可回收周转资产管理，水袋新收押金 5 元/个。“袋桶库存”每种桶袋只有三个数：店里、客户手里、已报废（累计），点哪个数就能直接改，没改的数不动；新买的点「新购」加到店里，坏了扔掉的点「报废」从店里转到已报废（最多报废店里现有的）；领桶、还桶、破损登记会自动增减，店里和客户手里记到 0 为止，不会因此拦住交付。合计 = 店里 + 客户手里 + 会员退回待确认报废，已报废不算在内。每种桶袋可设“店里少于多少个时提醒”，低于时菜单显示“偏少”。每次新购、报废和修改都留记录（改前 → 改后、备注、经办人），可导出。“袋桶台账”独立展示会员持有、全部周转流水（含店里的新购和门店报废）和破损报废。破损归还先暂占原押金（可一键选择常用破损原因），确认报废时选择按原实收批次扣押金或不扣押金（水站承担），同步更新库存及财务流水。
