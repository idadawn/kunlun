## 1. 背景与目标

水站需要统一管理会员、充值赠水、押金、自提配送及桶袋流转，解决水费、水票、押金和容器数量混合记账导致的对账困难，并保证三端业务数据一致。

### 1.1 产品目标

1. 建立完整会员档案，集中查询充值、赠水、用水、押金及桶袋领还记录。
2. 水费、水票、押金、桶袋数量独立记账，所有变动可追溯。
3. 支持自提与配送差异化充值方案，桶装水与袋装水分别管理。
4. 打通下单、预占、履约、核销及取消释放的完整水单流程。
5. 准确反映站内库存、配送在途、会员持有及可退押金额度。
6. 通过权限控制、操作留痕、幂等及关联纠错降低误操作风险。

### 1.2 成功指标

以下指标用于上线后的业务验收与运营观察，具体目标值在试运行后确定：

- 水单、充值、押金、容器记录均可关联到会员、单号、时间和操作人。
- 水票不存在透支，重复提交不产生重复入账。
- 任一会员的押金余额、容器持有量及可退额度可核对。
- 管理端汇总与业务明细口径一致，可导出对账。
- 三端查询同一业务时状态与数量一致。

### 3.3 数据隔离

- 会员所有查询必须在服务端按当前登录会员过滤，不能仅隐藏前端入口。

- 停用员工账号后，其既有业务记录保留，登录及操作权限立即失效。
- 权限变更不影响历史单据中的原操作人信息。

## 4. 核心概念与数据口径

### 4.1 水品与领取方式

- 水品：桶装水、袋装水。
- 领取方式：自提、配送。
- 水票按“水品 + 领取方式”分账，首期形成四类水票：自提桶票、配送桶票、自提袋票、配送袋票。
- 不同类别默认不互换，不合并展示为可随意使用的统一余额。

### 4.2 四类独立账目

| 账目 | 单位 | 典型变动 |
| --- | --- | --- |
| 水费账 | 元 | 充值实收、经授权的关联纠错 |
| 水票账 | 桶或袋 | 充值购水、赠水、下单预占、交付扣减、取消释放 |
| 押金账 | 元及押金数量 | 交押金、补交、退款、关联纠错 |
| 容器账 | 个 | 领出、归还、在途、持有变动 |

规则：押金不参与充值赠水；交押金不等于领走容器；归还容器不等于已退押金。

### 4.3 水票口径

对每一类水票分别记录：

- 累计到账：购买到账与赠送到账之和。
- 可用数量：当前可用于新下单的数量。
- 预占数量：已下单但尚未完成或取消的数量。
- 已使用数量：已完成履约并核销的数量。

约束：

- `可用数量 >= 0`，`预占数量 >= 0`，`已使用数量 >= 0`。
- 下单时增加预占并等额减少可用。
- 完成时减少预占并增加已使用，不重复扣减。
- 取消时减少预占并等额恢复可用。
- 购买数量与赠送数量须分别留存，赠水扣减顺序待确认。

### 4.4 押金与容器口径

桶和袋分别记录：

- 已交押金数量及押金金额。
- 会员实际持有容器数量。
- 履约预占的新增容器占用数量。
- 当前可退押金数量及金额。

可退押金数量按以下原则计算：

`可退数量 = max(0, 未被实际持有或履约新增占用覆盖的已交押金数量)`

退款金额按原押金收款记录的实际单价计算，不使用修改后的当前单价。具体退款批次选择规则见第 16 章待确认项。

### 4.5 容器数量口径

管理端至少分别展示桶、袋的：

- 容器总量。
- 站内可用数量。
- 配送在途数量。
- 会员实际持有数量。
- 回收待检数量（如启用该状态）。
- 异常数量及异常明细。

库存台账和会员持有台账可以按单据联动，但须保留独立流水，不能只保存汇总值。

## 5. 信息架构

### 5.1 管理端 PC

1. 经营总览：实收、用水、待履约、容器持有、趋势和待办。

4. 充值与押金：充值记录、押金收支、退款核对、统计导出。
5. 桶袋台账：库存、在途、会员持有、领还明细、异常记录。
6. 业务设置：优惠方案、押金单价、容器设置、员工权限、备份设置。

### 5.2 员工端小程序

1. 工作台：班次、个人业绩、待办水单和快捷入口。
2. 水单：待接单、配送中、待自提、历史水单。
3. 会员：查询、新建、会员资产摘要和业务办理。
4. 我的：个人业务记录、收款对账、当前门店和账号信息。

### 5.3 会员端小程序

1. 首页：水票摘要、配送/自提入口、进行中水单、押金与容器摘要。
2. 水单：进行中、已完成、已取消及详情。
3. 资产：分类水票、押金、实际持有、可退额度和变动记录。
4. 我的：姓名、电话、配送地址及联系水站。

## 6. 会员管理需求

### 6.1 会员字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 会员编号 | 系统生成 | 全站唯一，创建后不可修改 |
| 姓名 | 是 | 去除首尾空格，长度及字符规则由设计统一 |
| 联系电话 | 是 | 用于查询及账号识别，重复处理规则待确认 |
| 配送地址 | 配送时必填 | 保存小区/地址、楼栋单元、门牌号及必要说明 |
| 会员状态 | 系统生成 | 正常、停用；停用是否限制下单待确认 |
| 备注 | 否 | 员工或管理员填写 |
| 创建时间/来源 | 系统生成 | 会员注册、员工新建或历史导入 |

### 6.2 查询与新建

- 支持按姓名、电话、会员编号查询。
- 员工办理业务前必须选定唯一会员。
- 未找到会员时可进入新建流程，新建成功后返回原业务。
- 姓名、电话未通过校验时不得保存。
- 配送地址可在下单时补充，非配送会员允许暂不填写。

### 6.3 会员 360° 详情

至少展示：

- 基础资料、状态和会员编号。
- 四类水票的可用、预占及已使用数量。
- 桶、袋押金数量与金额。
- 实际持有桶袋和可退押金额度。
- 充值、赠水、用水、押金、容器领还及纠错记录。
- 快捷入口：充值、押金、代开水单、登记领还。

## 7. 充值与优惠需求

### 7.1 优惠方案字段

| 字段 | 说明 |
| --- | --- |
| 方案名称 | 便于员工识别，如“桶装水配送畅享包” |
| 充值金额 | 本方案应收水费，不包含押金 |
| 适用水品 | 桶装水或袋装水，可关联具体规格 |
| 领取方式 | 自提或配送 |
| 购买数量 | 按金额购得的水票数量 |
| 赠送数量 | 额外赠送的水票数量 |
| 状态 | 启用、停用 |
| 生效时间 | 建议保留，具体是否支持定时生效应在评审时确认 |
| 创建/修改信息 | 操作人和时间 |

同样金额允许因自提/配送不同而配置不同购买及赠送数量。

### 7.2 水费充值流程

1. 员工选择或新建会员。
2. 系统展示当前可用优惠方案。
3. 员工选择方案，系统展示水品、领取方式、购买数量、赠送数量、到账总数及实收金额。
4. 员工选择收款方式并确认实际已收款。
5. 服务端校验方案状态、会员状态和请求唯一性。
6. 在同一事务中保存充值单、水费实收、购水及赠水水票流水。
7. 返回充值结果和最新水票余额。

### 7.3 充值快照

每笔充值必须保存：

- 原方案 ID 和方案名称。
- 当时的充值金额、水品、领取方式、购买数量和赠送数量。
- 实际收款金额及收款方式。
- 会员、操作人、时间和业务单号。

后续修改或停用方案不得改变历史充值记录。

### 7.4 充值异常

- 重复点击或网络重试不得重复收款、重复赠水。
- 任一子账写入失败时整笔充值失败，不允许只增加水票但未保存实收。
- 充值错误通过关联原充值单的纠错记录处理；是否允许水费退款及其规则待确认。

## 8. 押金管理需求

### 8.1 独立入口

员工端提供独立的“交押金/押金充值”入口，支持：

- 首次预交押金。
- 新增领用前补交押金。
- 押金退款前的额度核对。
- 押金退款登记。
- 查询押金流水和关联容器记录。

不得将押金金额混入水费充值金额，也不得触发赠水。

### 8.2 交押金流程

1. 选择会员。
2. 选择桶或袋及数量。
3. 系统按当前押金单价试算应收金额。
4. 员工确认实际收款并登记收款方式。
5. 系统增加对应押金数量和金额，保存单价及收款快照。
6. 容器持有数量不因交押金而变化。

### 8.3 新增领用与补交

- 已交押金覆盖的容器正常等量换水，不重复收押金。
- 当本次新增领用导致押金覆盖不足时，系统提示需补交的容器数量及金额。
- 未补足时是否允许继续履约由第 16 章规则决定；原型按“不足需补交”设计。
- 实际领出、收回空容器和押金收款分别生成流水，并通过会员及水单关联。

### 8.4 退押金流程

1. 员工选择会员和容器类型。
2. 系统展示已交押金、实际持有、履约新增占用及可退额度。
3. 如先归还容器，先登记实际归还数量并更新持有台账。
4. 系统按原押金收款金额计算可退金额。
5. 员工复核后确认退款，保存实际退款金额、方式、操作人和时间。
6. 退押金不自动修改会员实际持有数量。

无可退额度时不得提交成功，并展示占用原因及关联水单/容器记录。

## 9. 水单与履约需求

### 9.1 下单字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 水单号 | 系统生成 | 全局唯一 |
| 会员 | 是 | 会员下单自动带入本人 |
| 下单来源 | 系统生成 | 会员下单或员工代开 |
| 领取方式 | 是 | 自提或配送 |
| 水品及规格 | 是 | 桶装水或袋装水 |
| 下单数量 | 是 | 正整数，不能超过对应可用水票 |
| 配送地址 | 配送必填 | 默认带入会员地址，可选择或修改 |
| 期望时间 | 否 | 营业时段及配送规则待确认 |
| 备注 | 否 | 会员或员工填写 |
| 操作人 | 系统生成 | 会员本人或代开员工 |

### 9.2 水单状态

| 状态 | 适用 | 说明 |
| --- | --- | --- |
| 待接单 | 配送 | 已创建并预占水票，等待员工接单 |
| 待自提 | 自提 | 已创建并预占水票，等待到店交付 |
| 配送中 | 配送 | 员工已接单，可记录在途容器 |
| 已完成 | 全部 | 已确认实际交付，水票及容器完成核销 |
| 已取消 | 全部 | 水单关闭，预占水票已释放 |
| 异常 | 全部，可选 | 履约存在差异或异常，需人工处理；具体规则待确认 |

状态必须按允许路径变化，不能直接删除历史水单。

### 9.3 配送主流程

会员下单或员工代开 → 校验并预占水票 → 员工接单 → 配送中 → 确认实际交付 → 扣减预占水票 → 登记容器领出和收回 → 完成并留痕。

### 9.4 自提主流程

会员下单或员工代开 → 校验并预占水票 → 生成待自提水单 → 员工核对会员 → 确认实际交付 → 扣减预占水票 → 登记容器领出和收回 → 完成并留痕。

### 9.5 确认交付

交付页至少包含：

- 原水单号、会员、领取方式、水品和下单数量。
- 实际交付水量。
- 实际新增领出容器数。
- 收回空容器数。
- 押金覆盖校验结果。
- 交付时间、操作人及必要备注。

等量换水示例：交付 2 桶、收回空桶 2 个、新增领出 0 个，会员持有数量不变，不重复收押金。

实际交付与下单不一致时，不得简单覆盖原单数量；应保存原下单数量、实际交付数量及差异原因，并同步调整预占。超出原预占部分须重新校验可用水票，不足时不得透支。

### 9.6 取消规则

- 取消成功后释放全部未履约预占水票及容器新增占用。
- 已交付或已完成部分不能直接通过整单取消冲回，应走关联纠错流程。
- 可取消状态、取消角色、接单后是否允许取消及原因必填规则待确认。

## 10. 桶袋台账需求

### 10.1 领还登记

支持从履约单联动登记，也支持经授权的独立登记：

- 容器类型及规格。
- 实际领出数量。
- 收回空容器数量。
- 关联会员和水单（独立登记时水单可选）。
- 操作人、时间、备注。
- 登记前后会员持有数量。

独立登记只改变容器账，不扣水票、不自动退押金。

### 10.2 管理端台账

- 分别查看桶、袋库存和流转汇总。
- 查看配送在途数量及关联配送水单。
- 查看会员持有量排行及单个会员持有明细。
- 查看每笔领还流水和关联操作人。
- 支持按时间、会员、容器类型、水单及操作人筛选导出。
- 支持库存预警值配置；预警不直接修改库存。

### 10.3 异常容器

损坏、遗失、自带容器及回收待检规则待确认。未确认前，原型中的相关分类仅作信息架构示意，不作为验收口径。

## 11. 管理端统计与导出

### 11.1 经营总览

- 今日水费实收、押金实收及合计。
- 今日完成用水量，桶、袋分列。
- 待接单、配送中、待自提和今日完成水单数。
- 会员持有桶、袋及配送在途数量。
- 近 7 日水费实收和用水趋势。
- 待退押金、库存预警等待办事项。

“今日”默认按水站经营时区的自然日统计；如存在跨日营业，口径需另行确认。

### 11.2 报表范围

- 会员列表及会员资产快照。
- 水单汇总和履约明细。
- 充值实收、购水及赠水明细。
- 押金收支和可退额度明细。
- 容器领还及会员持有明细。
- 操作日志和关联纠错记录（按权限）。

### 11.3 导出要求

- 导出沿用当前筛选条件和当前账号数据权限。
- 明确导出字段、时间范围、数量单位及金额单位。
- 导出文件建议采用 CSV 或 XLSX；原型演示 CSV。
- 大量数据导出不能阻塞正常业务，具体异步阈值由技术设计确定。
- 导出行为记录操作人和时间。

## 12. 设置需求

### 12.1 优惠方案

支持新建、编辑、启用和停用方案；历史充值保留快照。

### 12.2 押金与容器

- 桶、袋分别设置押金单价。
- 设置容器规格、总量和库存预警值。
- 修改押金单价只影响之后的押金收款，不影响历史退款原价。
- 水袋押金对应实物及回收方式确认后方可定稿相关配置。

### 12.3 员工权限

- 支持员工账号新建、启用、停用和角色配置。
- 权限至少覆盖会员、充值、押金、退款、水单、容器、报表和设置。
- 管理员不得通过操作导致系统失去最后一个可用管理账号。

### 12.4 数据备份

- 支持自动备份策略、最近备份时间和结果展示。
- 支持手动触发备份。
- 备份数据访问权限与全站管理权限一致。
- 恢复流程须经过技术评审和二次确认，不在普通业务页面提供一键覆盖。

## 13. 通用业务规则

1. 水费、水票、押金、容器数量分别记账。
2. 水票按水品和领取方式分别管理，默认不互换。
3. 下单预占、完成核销、取消释放；任何环节不得出现负可用水票。
4. 押金不参与充值赠水，押金金额不进入水费实收。
5. 等量换水不重复收押金，新增领用须校验押金覆盖。
6. 只有未被实际持有或履约新增占用的押金可退，按原收取金额退款。
7. 所有业务保留唯一单号、创建时间、操作人及必要的关联单号。
8. 提交、网络重试及重复消息必须执行幂等校验。
9. 已完成业务不得物理删除或直接篡改，通过关联原单的纠错记录处理。
10. 汇总值与流水必须可对账；流水和汇总更新须保证事务一致性。
11. 三端共享同一数据源，不以各端本地数据作为最终账目。
12. 金额使用定点小数计算，禁止浮点误差进入账务结果。

## 14. 非功能需求

### 14.1 安全

- 三端真实登录，密码等敏感凭据不得明文保存。
- 所有业务接口执行身份、角色和数据权限校验。
- 会员只能访问本人资料和业务记录。
- 关键操作记录登录账号、操作人、时间、对象和结果。
- 导出、退款、设置及纠错等高风险操作需防重复提交并保留审计记录。
- 具体会话时长、登录失败锁定和二次验证策略由安全设计确定。

### 14.2 易用性

- 员工端和会员端优先适配常见手机屏幕，核心按钮易于单手点击。
- 充值、交押金、代开水单等高频入口置于员工工作台。
- 数量、金额、单位及水票类别必须同时清晰展示。
- 失败提示说明原因和可执行的下一步，不能只提示“操作失败”。
- 加载期间防止重复提交；成功后展示单号及关键结果。

### 14.3 性能与可用性

- 常规查询和页面操作在正常网络下应有及时反馈，具体响应指标由技术评审确定。
- 账务写入必须具备事务和并发控制，避免并发下单造成超扣。
- 数据定期备份，并进行恢复可用性验证。
- 浏览器兼容范围在研发评审时明确。

### 14.4 日志与审计

日志至少包括登录、会员资料变更、充值、押金收退、水单状态变化、容器领还、方案设置、权限设置、导出和纠错。业务日志不可被普通员工删除。

## 15. 核心验收场景

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-01 | 新建必填项完整的会员 | 生成唯一会员编号，可查询并办理业务 |
| AC-02 | 选择自提和配送同价方案 | 可按配置得到不同购买/赠送数量，历史保存方案快照 |
| AC-03 | 水费充值时同时需要交押金 | 水费与押金分别生成记录，押金不参与赠水 |
| AC-04 | 可用水票不足时下单 | 下单失败，不产生预占和负数余额 |
| AC-05 | 连续重复提交同一充值或水单请求 | 仅入账一次，返回同一业务结果 |
| AC-06 | 下单后取消 | 水单变为已取消，对应水票及容器预占释放 |
| AC-07 | 完成配送或自提 | 预占转为已使用，不重复扣减，保存实际交付及容器流水 |
| AC-08 | 已有押金容器等量换水 | 不重复收押金，收回和领出分别留痕，持有量按规则变化 |
| AC-09 | 新增领用超过押金覆盖 | 提示补交数量与金额，不允许静默超额办理 |
| AC-10 | 容器归还但未申请退押金 | 持有量减少，押金仍保留，两条账目可独立核对 |
| AC-11 | 押金被持有或履约占用时退款 | 可退金额正确，超额退款被阻止并显示原因 |
| AC-12 | 修改押金单价后退还历史押金 | 按原收取单价计算，不使用新单价 |
| AC-13 | 修改或停用优惠方案 | 已发生充值的金额、购水和赠水快照不变 |
| AC-14 | 实际交付数量与下单不同 | 保存差异，正确调整预占；超出部分不足时不得透支 |
| AC-15 | 会员尝试访问他人记录 | 服务端拒绝，不返回他人数据 |
| AC-16 | 员工无退款或设置权限 | 入口和接口均不能越权执行 |
| AC-17 | 已完成业务发生错误 | 通过关联原单纠错，原单和纠错记录均可查询 |
| AC-18 | 管理端导出筛选后的报表 | 导出范围、权限和页面口径一致 |
| AC-19 | 三端查看同一水单 | 当前状态、数量和关键业务结果一致 |
| AC-20 | 查看经营及容器汇总 | 汇总可由对应业务明细核对，桶袋不混算 |

## 16. 待确认事项

以下事项未确认前，不得以原型演示值替代正式规则：

1. 自提、配送各方案的充值金额、购买数量和赠送数量。
2. 桶、袋押金单价，以及水袋押金对应的具体实物和回收方式。
3. 赠水扣减顺序、赠水有效期及购买水票有效期。
4. 水费退款、水票兑换、转赠和发票规则。
5. 押金退款批次选择规则，以及部分退款时的原价计算顺序。
6. 配送费、配送范围、营业时段、期望时间和取消条件。
7. 实际交付差异的允许范围、原因选项和审批要求。
8. 桶袋损坏、遗失、赔偿、自带容器和回收待检的处理方式。
9. 历史会员数据是否导入，以及导入字段、初始账目核对和去重方式。
10. 会员注册登录方式、手机号变更流程及重复手机号处理规则。
11. 押金退款是否允许会员发起申请，以及是否需要管理员复核。
12. 押金覆盖不足时是否绝对禁止新增领用，或允许特定角色例外处理。
13. 会员停用后的下单、退款和既有水单处理规则。
14. 单店或多店扩展要求、经营时区及跨日统计口径。
15. 数据备份频率、保留周期、恢复目标和权限审批流程。
