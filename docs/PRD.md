## 1. 背景与目标

水站需要统一管理会员、充值赠水、押金、自提配送及桶袋流转，解决水费、水票、押金和容器数量混合记账导致的对账困难，并保证三端业务数据一致。

### 1.1 产品目标

1. 建立完整会员档案，集中查询充值、赠水、用水、押金及桶袋领还记录。
2. 水费、水票、押金、桶袋数量独立记账，所有变动可追溯。
3. 支持自提与配送差异化充值方案，桶装水与袋装水分别管理。
4. 打通下单、预占、履约、核销及取消释放的完整水单流程。
5. 准确反映站内库存、配送在途、会员持有及可退押金额度。
6. 通过权限控制、操作留痕、幂等及关联纠错降低误操作风险。

### 1.2 成功指标

以下指标用于上线后的业务验收与运营观察，具体目标值在试运行后确定：

- 水单、充值、押金、容器记录均可关联到会员、单号、时间和操作人。
- 水票不存在透支，重复提交不产生重复入账。
- 任一会员的押金余额、容器持有量及可退额度可核对。
- 管理端汇总与业务明细口径一致，可导出对账。
- 三端查询同一业务时状态与数量一致。

## 4. 核心概念与数据口径

### 4.1 水品与领取方式

- 水品：首期为桶装水、袋装水；管理员可新增水品，新增时选择用周转桶还是周转水袋装（决定收哪种押金、算哪种袋桶库存，添加后不能修改）。
- 领取方式：自提、配送。
- 水票按“水品 + 领取方式”分账：每种水品分别记自提票和配送票，首期两种水品即四类水票（自提桶票、配送桶票、自提袋票、配送袋票）；新增水品单独建套餐、单独记票。
- 不同类别默认不互换，不合并展示为可随意使用的统一余额。

### 4.2 四类独立账目

| 账目 | 单位 | 典型变动 |
| --- | --- | --- |
| 水费账 | 元 | 充值实收、经授权的关联纠错 |
| 水票账 | 桶或袋 | 充值购水、赠水、下单预占、交付扣减、取消释放 |
| 押金账 | 元及押金数量 | 交押金、补交、退款、关联纠错 |
| 容器账 | 个 | 领出、归还、在途、持有变动 |

规则：押金不参与充值赠水；交押金不等于领走容器；归还容器不等于已退押金。

### 4.3 水票口径

对每一类水票分别记录：

- 累计到账：购买到账与赠送到账之和。
- 可用数量：当前可用于新下单的数量。
- 预占数量：已下单但尚未完成或取消的数量。
- 已使用数量：已完成履约并核销的数量。

约束：

- `可用数量 >= 0`，`预占数量 >= 0`，`已使用数量 >= 0`。
- 下单时增加预占并等额减少可用。
- 完成时减少预占并增加已使用，不重复扣减。
- 取消时减少预占并等额恢复可用。
- 购买数量与赠送数量须分别留存，赠水扣减顺序待确认。

### 4.4 押金与容器口径

桶和袋分别记录：

- 已交押金数量及押金金额。
- 会员实际持有容器数量。
- 履约预占的新增容器占用数量。
- 当前可退押金数量及金额。

可退押金数量按以下原则计算：

`可退数量 = max(0, 未被实际持有或履约新增占用覆盖的已交押金数量)`

退款金额按原押金收款记录的实际单价计算，不使用修改后的当前单价。具体退款批次选择规则见第 16 章待确认项。

### 4.5 容器数量口径

管理端至少分别展示桶、袋的：

- 容器总量。
- 站内可用数量。
- 配送在途数量。
- 会员实际持有数量。
- 回收待检数量（如启用该状态）。
- 异常数量及异常明细。

库存台账和会员持有台账可以按单据联动，但须保留独立流水，不能只保存汇总值。

## 7. 充值与优惠需求

### 7.1 优惠方案字段

| 字段 | 说明 |
| --- | --- |
| 方案名称 | 便于员工识别，如“桶装水配送畅享包” |
| 充值金额 | 本方案应收水费，不包含押金 |
| 适用水品 | 桶装水或袋装水，可关联具体规格 |
| 领取方式 | 自提或配送 |
| 购买数量 | 按金额购得的水票数量 |
| 赠送数量 | 额外赠送的水票数量 |
| 状态 | 启用、停用 |
| 生效时间 | 建议保留，具体是否支持定时生效应在评审时确认 |
| 创建/修改信息 | 操作人和时间 |

同样金额允许因自提/配送不同而配置不同购买及赠送数量。

### 7.2 水费充值流程

1. 员工选择或新建会员。
2. 系统展示当前可用优惠方案。
3. 员工选择方案，系统展示水品、领取方式、购买数量、赠送数量、到账总数及实收金额。
4. 员工选择收款方式并确认实际已收款。
5. 服务端校验方案状态、会员状态和请求唯一性。
6. 在同一事务中保存充值单、水费实收、购水及赠水水票流水。
7. 返回充值结果和最新水票余额。

### 7.3 充值快照

每笔充值必须保存：

- 原方案 ID 和方案名称。
- 当时的充值金额、水品、领取方式、购买数量和赠送数量。
- 实际收款金额及收款方式。
- 会员、操作人、时间和业务单号。

后续修改或停用方案不得改变历史充值记录。

### 7.4 充值异常

- 重复点击或网络重试不得重复收款、重复赠水。
- 任一子账写入失败时整笔充值失败，不允许只增加水票但未保存实收。
- 充值错误通过关联原充值单的纠错记录处理；是否允许水费退款及其规则待确认。

## 8. 押金管理需求

### 8.1 独立入口

员工端提供独立的“交押金/押金充值”入口，支持：

- 首次预交押金。
- 新增领用前补交押金。
- 押金退款前的额度核对。
- 押金退款登记。
- 查询押金流水和关联容器记录。

不得将押金金额混入水费充值金额，也不得触发赠水。

### 8.2 交押金流程

1. 选择会员。
2. 选择桶或袋及数量。
3. 系统按当前押金单价试算应收金额。
4. 员工确认实际收款并登记收款方式。
5. 系统增加对应押金数量和金额，保存单价及收款快照。
6. 容器持有数量不因交押金而变化。

### 8.3 新增领用与补交

- 已交押金覆盖的容器正常等量换水，不重复收押金。
- 当本次新增领用导致押金覆盖不足时，系统提示需补交的容器数量及金额。
- 未补足时是否允许继续履约由第 16 章规则决定；原型按“不足需补交”设计。
- 实际领出、收回空容器和押金收款分别生成流水，并通过会员及水单关联。

### 8.4 退押金流程

1. 员工选择会员和容器类型。
2. 系统展示已交押金、实际持有、履约新增占用、审核中数量及可申请额度。
3. 如先归还容器，先登记实际归还数量并更新持有台账。
4. 员工提交退押金申请（数量、会员希望的退款方式、原因），此时不动押金。
5. 管理员在「退款审核」核对后通过：按原押金收款批次重新计算并退款，保存实际退款金额、方式、审核人和时间；或填写原因驳回，账目不变。
6. 退押金不自动修改会员实际持有数量。

无可退额度时不得提交成功，并展示占用原因及关联水单/容器记录。

## 9. 水单与履约需求

### 9.1 下单字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 水单号 | 系统生成 | 全局唯一 |
| 会员 | 是 | 会员下单自动带入本人 |
| 下单来源 | 系统生成 | 会员下单或员工代开 |
| 领取方式 | 是 | 自提或配送 |
| 水品及规格 | 是 | 桶装水或袋装水 |
| 下单数量 | 是 | 正整数，不能超过对应可用水票 |
| 配送地址 | 配送必填 | 默认带入会员默认收货地址，可选择其他地址或当场新增；下单后保存为本单快照 |
| 期望时间 | 否 | 营业时段及配送规则待确认 |
| 备注 | 否 | 会员或员工填写 |
| 操作人 | 系统生成 | 会员本人或代开员工 |

### 9.2 水单状态

| 状态 | 适用 | 说明 |
| --- | --- | --- |
| 待接单 | 配送 | 已创建并预占水票，等待员工接单 |
| 待自提 | 自提 | 已创建并预占水票，等待到店交付 |
| 配送中 | 配送 | 员工已接单，可记录在途容器 |
| 已完成 | 全部 | 已确认实际交付，水票及容器完成核销 |
| 已取消 | 全部 | 水单关闭，预占水票已释放 |
| 异常 | 全部，可选 | 履约存在差异或异常，需人工处理；具体规则待确认 |

状态必须按允许路径变化，不能直接删除历史水单。

### 9.3 配送主流程

会员下单或员工代开 → 校验并预占水票 → 员工接单 → 配送中 → 确认实际交付 → 扣减预占水票 → 登记容器领出和收回 → 完成并留痕。

### 9.4 自提主流程

会员下单或员工代开 → 校验并预占水票 → 生成待自提水单 → 员工核对会员 → 确认实际交付 → 扣减预占水票 → 登记容器领出和收回 → 完成并留痕。

### 9.5 确认交付

交付页至少包含：

- 原水单号、会员、领取方式、水品和下单数量。
- 实际交付水量。
- 实际新增领出容器数。
- 收回空容器数。
- 押金覆盖校验结果。
- 交付时间、操作人及必要备注。

等量换水示例：交付 2 桶、收回空桶 2 个、新增领出 0 个，会员持有数量不变，不重复收押金。

实际交付与下单不一致时，不得简单覆盖原单数量；应保存原下单数量、实际交付数量及差异原因，并同步调整预占。超出原预占部分须重新校验可用水票，不足时不得透支。

### 9.6 取消规则

- 取消成功后释放全部未履约预占水票及容器新增占用。
- 已交付或已完成部分不能直接通过整单取消冲回，应走关联纠错流程。
- 可取消状态、取消角色、接单后是否允许取消及原因必填规则待确认。

## 10. 桶袋台账需求

### 10.1 领还登记

支持从履约单联动登记，也支持经授权的独立登记：

- 容器类型及规格。
- 实际领出数量。
- 收回空容器数量。
- 关联会员和水单（独立登记时水单可选）。
- 操作人、时间、备注。
- 登记前后会员持有数量。

独立登记只改变容器账，不扣水票、不自动退押金。

### 10.2 管理端台账

- 分别查看桶、袋库存和流转汇总。
- 查看配送在途数量及关联配送水单。
- 查看会员持有量排行及单个会员持有明细。
- 查看每笔领还流水和关联操作人。
- 支持按时间、会员、容器类型、水单及操作人筛选导出。
- 支持库存预警值配置；预警不直接修改库存。

### 10.3 异常容器

损坏、遗失、自带容器及回收待检规则待确认。未确认前，原型中的相关分类仅作信息架构示意，不作为验收口径。

## 11. 管理端统计与导出

### 11.1 经营总览

- 今日水费实收、押金实收及合计。
- 今日完成用水量，桶、袋分列。
- 待接单、配送中、待自提和今日完成水单数。
- 会员持有桶、袋及配送在途数量。
- 近 7 日水费实收和用水趋势。
- 待退押金、库存预警等待办事项。

“今日”默认按水站经营时区的自然日统计；如存在跨日营业，口径需另行确认。

### 11.2 报表范围

- 会员列表及会员资产快照。
- 水单汇总和履约明细。
- 充值实收、购水及赠水明细。
- 押金收支和可退额度明细。
- 容器领还及会员持有明细。
- 操作日志和关联纠错记录（按权限）。

### 11.3 导出要求

- 导出沿用当前筛选条件和当前账号数据权限。
- 明确导出字段、时间范围、数量单位及金额单位。
- 导出文件建议采用 CSV 或 XLSX；原型演示 CSV。
- 大量数据导出不能阻塞正常业务，具体异步阈值由技术设计确定。
- 导出行为记录操作人和时间。

## 12. 设置需求

### 12.1 优惠方案

支持新建、编辑、启用和停用方案；历史充值保留快照。

### 12.2 押金与容器

- 桶、袋分别设置押金单价。
- 设置容器规格、总量和库存预警值。
- 修改押金单价只影响之后的押金收款，不影响历史退款原价。
- 水袋为可回收周转容器，新收押金 5 元/个（详见第 24 章）。

### 12.3 员工权限

- 支持员工账号新建、启用、停用和角色配置。
- 权限至少覆盖会员、充值、押金、退款、水单、容器、报表和设置。
- 管理员不得通过操作导致系统失去最后一个可用管理账号。

### 12.4 数据备份

- 支持自动备份策略、最近备份时间和结果展示。
- 支持手动触发备份。
- 备份数据访问权限与全站管理权限一致。
- 恢复流程须经过技术评审和二次确认，不在普通业务页面提供一键覆盖。

## 13. 通用业务规则

1. 水费、水票、押金、容器数量分别记账。
2. 水票按水品和领取方式分别管理，默认不互换。
3. 下单预占、完成核销、取消释放；任何环节不得出现负可用水票。
4. 押金不参与充值赠水，押金金额不进入水费实收。
5. 等量换水不重复收押金，新增领用须校验押金覆盖。
6. 只有未被实际持有或履约新增占用的押金可退，按原收取金额退款。
7. 所有业务保留唯一单号、创建时间、操作人及必要的关联单号。
8. 提交、网络重试及重复消息必须执行幂等校验。
9. 已完成业务不得物理删除或直接篡改，通过关联原单的纠错记录处理。
10. 汇总值与流水必须可对账；流水和汇总更新须保证事务一致性。
11. 三端共享同一数据源，不以各端本地数据作为最终账目。
12. 金额使用定点小数计算，禁止浮点误差进入账务结果。

## 14. 非功能需求

### 14.1 安全

- 三端真实登录，密码等敏感凭据不得明文保存。
- 所有业务接口执行身份、角色和数据权限校验。
- 会员只能访问本人资料和业务记录。
- 关键操作记录登录账号、操作人、时间、对象和结果。
- 导出、退款、设置及纠错等高风险操作需防重复提交并保留审计记录。
- 具体会话时长、登录失败锁定和二次验证策略由安全设计确定。

### 14.2 易用性

- 员工端和会员端优先适配常见手机屏幕，核心按钮易于单手点击。
- 充值、交押金、代开水单等高频入口置于员工工作台。
- 数量、金额、单位及水票类别必须同时清晰展示。
- 失败提示说明原因和可执行的下一步，不能只提示“操作失败”。
- 加载期间防止重复提交；成功后展示单号及关键结果。

### 14.3 性能与可用性

- 常规查询和页面操作在正常网络下应有及时反馈，具体响应指标由技术评审确定。
- 账务写入必须具备事务和并发控制，避免并发下单造成超扣。
- 数据定期备份，并进行恢复可用性验证。
- 浏览器兼容范围在研发评审时明确。

### 14.4 日志与审计

日志至少包括登录、会员资料变更、充值、押金收退、水单状态变化、容器领还、方案设置、权限设置、导出和纠错。业务日志不可被普通员工删除。

| AC-19 | 三端查看同一水单 | 当前状态、数量和关键业务结果一致 |
| AC-20 | 查看经营及容器汇总 | 汇总可由对应业务明细核对，桶袋不混算 |

本节取代前文充值赠送、赠票扣减顺序和水费退款待确认条款。沿用现有三端 HTML 页面实现真实接口和数据库事务，不重新设计页面。

- 管理员可新增、修改、停用套餐；金额、水品、领取方式和数量只影响新充值。每笔充值保存完整快照，不追溯改写已到账权益。
- 每笔充值形成独立水票批次，按水品和领取方式隔离。先充先分配，同批次先付费后赠送。下单预占到具体批次，取消原路释放；核销按实交付数量结算，数量差异需理由。

## 28. 退款审核与报废免扣押金（2026-10-27）

- **所有退款须管理员审核**：押金退款和退清充值剩余权益都改为先提交「退款申请」（申请单号 `SQ` + 日期 + 序号），提交时不退钱、不动押金和水票。员工在会员详情、押金弹窗或水票批次中提交；管理员在「财务管理 → 退款审核」（`/admin/refunds`）审核。

- **常用破损原因**：登记破损和确认报废时可一键选择原因——桶：桶身开裂漏水、桶口破损、提手断裂、磕碰变形、污染异味无法清洗、自然老化；袋：袋体破损漏水、袋口/阀门损坏、封口不严、污染无法清洗、自然老化。门店报废另有“盘点报损”。
- **报废不扣押金**：确认报废时可选「扣除押金」（默认）或「不扣押金（水站承担）」。不扣时库存照常减少、累计报废照常增加，暂占的押金释放回会员可用余额（可申请退还或抵新领用），周转流水记为“报废免扣押金”、扣押金额 0，不计入报废扣押统计和押金流水；对账公式不变。

验收：店员提交退押金后押金余额不变，管理员通过后才退款；驳回的水费申请不影响水票，重新申请后可通过；管理员直接退款也出现在“已通过”列表；免扣报废后会员押金余额不变、可退数量增加、财务扣押合计不变。

- **新增水品**：在「水品与押金标准」新增水品，填写名称、每桶/每袋容量、包装、零售价、起送量，并选择用周转桶还是周转水袋装。押金和袋桶库存跟着容器走，添加后不能修改。每种水品单独建充值套餐、单独记自提/配送水票，不能和其他水品互相抵用；会员管理、员工端、会员端和会员导出按水品分别列出余额。只有还没建过套餐、没有水票和水单的水品（例如加错的）可以删除。升级时原有两种水品的会员余额原样迁移，包括被未完成水单预占的部分。
- **袋桶库存分步盘点**（2026-11-15 起由第 31 节替代）：「开始盘点」依次问三件事：① 现在店里有多少个能用的（空的、满的都算，坏的不算）；② 客户手里大概有多少个；③ 店里有多少个坏了、要报废。前两步数不清时可选“说不清，先记为待核实”：该项显示“待核实”，现存总量显示为“至少 N 个”，店里数量待核实时不判断库存预警。客户手里多于登记在会员名下的部分记为“未登记在外”。报废数计入累计报废、不再算库存；店里数量说不清时，从上次的数字中扣掉这次报废的。每次盘点记入库存操作历史，保留盘点前后数值。新买的桶袋用「新买入库」登记；会员退回的破损桶袋仍在「袋桶台账」确认报废。
- **门店点单**：员工端和管理端不变。同一次结算里有多种用同一种容器的水时，换回空桶按交付顺序依次占用顾客手里的空桶，需补押金依次累计。
- **价目表**：自提组在前、配送组在后，组内按水品添加顺序；某种容器只有一种水时标题仍写“桶装水 / 袋装水”，有多种时写水品名。

验收示例：新增“18.9L 矿泉水”（周转桶，2 桶起送）并建自提 100 元 6 桶套餐；会员充值后矿泉水自提票 6 张，原 15L 桶装水票不变；不能用 15L 桶装水票给矿泉水下单；矿泉水交付按周转桶计持有和押金；已有套餐的水品删除时提示“这个水品已有充值套餐、水票或水单，不能删除”。盘点时店里选“说不清”，库存页显示“待核实”和“至少 N 个”。会员登录会员端看不到点单入口，调用下单接口被拒绝。

## 30. 手动赠送、审核开关与记录（2026-11-03）

客户要求每一步尽量简单，主要就是记账：充值时能手动送几桶，后台能设置要不要审核，充值、退押金和袋桶流转的记录要一眼看清。本节为准，替代第 18、28 节中冲突的条款。

- **充值时手动赠送**：水费充值弹窗里套餐直接平铺成卡片（水品多时可按“水品 · 自提/配送”筛选），点一下就选中；下面用“− / +”填“另外赠送几桶”（不送就是 0，单次最多 1000），收款方式点按钮选；底部写清“到账 N 桶（付费 + 赠送）”和应收金额，按钮写“确认已收 ¥金额”。套餐本身仍然只有固定付费数量，赠送只在充值时手动给。
- **两个审核开关**：管理端「财务管理 → 审核」（原「退款审核」，`/admin/refunds`）顶部有两个开关，只有管理员能改，默认都打开：
  1. **店员手动赠送要审核**：打开时，店员填的赠送先记为待审核，付费水票当场到账，赠送等管理员批准后才到账；驳回就不送，充值本身不受影响。关闭时赠送当场到账。
  2. **店员退押金、退水费要审核**：打开时店员只能提交申请（和第 28 节一样）；关闭时店员当场就能退款，按钮从“申请退押金 / 提交退款申请”变成“退押金 / 确认已退款”。
  管理员自己充值赠送、退押金、退水费总是直接生效，不用再走一遍审核。不管开关怎么设，每笔赠送和退款都在审核页留有记录：直接办理的记为“已通过”，备注“管理员直接办理”或“无需审核，直接退款”。
- **审核页**：待审核、已通过、已驳回三类，类型分“充值赠送 / 押金退款 / 水费退款”。充值赠送显示送几桶、哪笔充值、收了多少钱，管理员可“批准赠送”或驳回（常用原因：不符合赠送规则、赠送数量不对、会员没有要求赠送）。菜单角标和经营总览待办显示待审核笔数。赠送还在审核时这笔充值被退款，赠送自动作废。
- **退款原因选填**：退押金和退清水费的原因都改为选填，常用原因一键选择。
- **记录更清楚**：
  - 充值记录：“到账水票”写总数和“付费 N + 赠送 M”，赠送待批准或未批准时加标签；详情里写赠送由谁批准或为什么没批准。
  - 退押金、退水费记录：经办人写“谁申请 / 谁审核退款”，押金流水同时显示退款原因和报废原因。
  - 袋桶台账默认打开「流转记录」，每一行用白话写“领走 2 个，还回 1 个”“破损还回 1 个”“报废 1 个”，并写清会员手里“3 → 4 个”、扣了多少押金、来自哪张水单或单独登记、谁经办。
- **登记领还更直观**：先选桶还是袋，卡片上直接显示会员手里现有几个；领走、还回用“− / +”填，下面预览“登记后会员手里 X → Y 个”，还回多于手里的会提示核对。收退押金的数量同样用“− / +”，收付方式点按钮。

验收：开关都打开时，店员给会员充值 100 元 16 桶并赠送 2 桶，会员当场有 16 桶，审核页出现一条“充值赠送 2 桶”；管理员批准后变成 18 桶，充值记录显示“18 桶，付费 16 + 赠送 2”。关掉两个开关后，店员赠送当场到账，店员退押金当场退款，押金流水经办人显示该店员。管理员自己赠送和退押金不进待审核。只有管理员能改开关。

## 31. 袋桶库存：三个数随时改（2026-11-15）

客户反馈袋桶库存的分步盘点太复杂，只要随时能更新店里、客户手里和报废的数量。本节为准，替代第 29 节的“袋桶库存分步盘点”。

- **只有三个数**：每种水品的配套桶袋一张卡片，显示「店里」（能用的，空的满的都算）、「客户手里」（拿走还没还的）、「已报废」（累计）。合计 = 店里 + 客户手里 + 会员退回待确认报废，已报废不算在合计里。取消“说不清 / 待核实”“至少 N 个”和“未登记在外”。
- **随时直接改**：点卡片上的任一个数（或「修改数量」）打开同一个弹窗，三个数预先填好现在的值，用“− / +”或直接输入，改哪个填哪个，没改的数不动；弹窗显示每个数“原来 → 现在”和合计变化。多报废了几个而店里没改时，提示“是从店里拿出来的？”并可一键把店里也减掉。客户手里少于登记在会员名下的数量时提示可能有会员还了没登记，可到袋桶台账核对；多于时说明有几个没登记到人。备注选填，可一键选“核对实际数量 / 会员还桶（袋）没登记 / 之前记错了”。
- **新购 / 报废快捷按钮**：卡片底部有「新购」「报废」两个按钮，填个数就能一步登记：新购加到店里；报废从店里拿出来、加到已报废，最多报废店里现有的，店里为 0 时「报废」不可点。弹窗显示店里（报废时还有已报废）“原来 → 现在”和合计变化；原因选填，可一键选“新买了一批 / 供应商补货 / 供应商赠送”或“破了 / 漏水 / 太旧了 / 清点时发现坏了”。会员退回的破损仍在袋桶台账登记。
- **自动跟着变**：会员领走时店里减、客户手里加，还回时反过来；店里和客户手里都是手记的数，各自记到 0 为止，不会因此拦住交付或还桶。会员破损归还时客户手里减、待确认报废加；在台账确认报废后待确认报废减、已报废加。会员名下的数量只随领还和破损登记变化，作为客户手里的参考。
- **提醒线**：弹窗里可设“店里少于多少个时提醒”，填 0 不提醒；店里低于提醒线时卡片变橙色、菜单角标显示“偏少”，经营总览待办同步提示。
- **修改记录**：每次修改、新购、门店报废和会员破损报废都记一笔，用白话写“店里 198 → 196 · 已报废 0 → 2”“提醒线 80 → 20”，含备注、关联会员和经办人，可按桶袋筛选、导出（改前 / 改后的店里、客户手里、已报废和合计）。原来的盘点记录照常显示。
- **升级**：原客户手里 = 会员名下 + 盘点时记的“未登记在外”；原来标为“待核实”的数按上次记下的数显示，可随时再改；各桶袋合计不变。

验收：店里 198、已报废 0 时把已报废改成 2 并一键“店里也减 2 个”，保存后店里 196、已报废 2、合计 198，修改记录显示“店里 198 → 196 · 已报废 0 → 2”。只改已报废时店里和客户手里不变。把店里改成 0 后照样能给会员交付，店里停在 0、客户手里加 1，并提示偏少；把提醒线改成 0 后不再提示。会员破损归还 1 个后客户手里减 1，确认报废后已报废加 1、合计减 1。点「新购」登记 20 个后店里和合计各加 20，记录显示“新购 · 店里 196 → 216”；点「报废」登记 2 个后店里减 2、已报废加 2、合计减 2，报废数量不能超过店里现有的。

## 32. 员工手机端与按角色开通功能（2026-11-16）

员工主要在手机上干活，不同角色要办的事不一样。管理员在管理端「系统设置 → 移动端配置」（`/admin/mobile`）按角色决定员工手机端能用哪些功能、首页怎么排；右侧手机框实时预览这个角色打开手机看到的首页。本节为准，补充第 3.2 节权限矩阵与第 5.2 节员工端。

- **功能清单**：门店点单、水单履约、自提核销、会员查询、新建会员、水费充值、收押金、退押金、登记领还、袋桶库存（手机端新增）、今日经营（首页卡片，手机端新增）。每项写明员工能做什么；袋桶库存（可直接改库存数）和今日经营（可看、可导出全站经营数据）标为“高风险”。

- 手机框只出现在管理端配置页的预览里，员工端、会员端页面本身仍不显示手机样机或假状态栏（第 19 节）。

## 33. 点单看清桶袋押金、会员整页档案与「可能要退的钱」（2026-11-16）

- **点单先看手里的桶袋**：门店点单（管理端弹窗、员工端「点单」页）选好顾客后，水品上方每种配套桶袋一张小卡：手里几个、已交押金多少钱（几个），并标出「押金够」「可退 N 个 ¥X」或「押金少 N 个」；有待报废的另行注明。水品卡片写“押金 ¥x/个 · 手里 N 个空桶可换”。
- **清空购物车**：选了水品后，底部购物袋出现「清空」，一点就清掉已选数量和换回空桶的改动，回到“还没有选水”。确认结算页不显示，已经开始提交的单只能在水单里处理。
- **会员 360° 档案改为整页**：会员列表点「360° 档案」打开整页（`/admin/members?id=会员ID`，可直接打开、刷新、用浏览器前进后退），取代原来的右侧抽屉。页头是会员概况和常用办理（点单、水费充值、收押金、退押金、登记领还）；下面五个数：可用水票、手里的桶袋、已交押金（现在就能退多少）、没用完的水费、可能要退的钱。左侧是各水品自提 / 配送票和水单占用、充值批次（在用的直接显示，已用完 / 已退款的点开再看，可直接退清剩余水票）、最近记录（水单、充值、押金各最近 8 条）；右侧是每种桶袋的手里、已交押金、现在可退，基础资料与登录账号，收货地址。「返回会员列表」回到原来的搜索、筛选、页码和滚动位置。
- **可能要退的钱**：押金和会员还没用完的水费都收在账上，但会员退桶、退水费时要还回去，不是赚的钱。工作台新增卡片「可能要退给会员的钱」：押金在池（多少个桶袋，已还桶、现在就能退多少）＋ 没用完的水费（剩余付费水票按原实付单价折算，赠票退款时收回、不退钱）＝ 合计可能要退；并把水费净收拆成“会员已经用掉的（真正的收入）＋ 还没用完的（可能要退）”。历史余额水票没有原价，只列张数、不计入金额。水费充值页的「水费净收」注明其中没用完的金额；会员档案按同一口径显示这位会员的数。
- **口径**：没用完的水费 = 每个在用充值批次 原实付 × 剩余付费票 ÷ 固定票数（舍入到分）之和，与退清该批次时实际退的钱一致；被未完成水单占着的票也计入，只是要等水单完成或取消后才能退。押金在池 = 各押金批次 剩余个数 × 原收款单价 之和（含待报废占用的部分）。

验收：顾客手里 2 桶、已交 2 桶押金，点单页显示“手里 2 个桶 · 已交押金 ¥100.00 · 2 个”并标「押金够」；登记还回 1 桶后标「可退 1 个 ¥50.00」。选好 3 件水后点「清空」，购物袋回到“还没有选水”。会员充值 100 元 16 桶、用掉 2 桶后，工作台“没用完的水费”增加 87.50 元、“会员已经用掉的”增加 12.50 元，合计可能要退同步增加；退清该批次后没用完的水费回落，退款正好 87.50 元。会员档案整页刷新后仍停在该会员，返回列表回到原来的位置。

## 34. 补录会员上系统前的数据（2026-11-17）

很多会员在水站用这套系统之前就买过套餐、交过押金，手里还拿着桶，系统里查不到。新增「补录会员上系统前的数据」权限，用来记下每位老会员：
- 买的什么套餐、现在还剩多少；
- 交过多少押金；
- 手里有几个桶袋。

本节补充第 3.2 节权限矩阵。

- **谁能补录**：默认只有管理员。已有的管理员账号升级后自动获得这个权限，不用重新登录。店员、送水员没有，「移动端配置」也开通不了。没有权限时看不到入口，直接调用接口会被拒绝。
- **在哪补录**：会员整页档案页头的「补录历史数据」。弹窗里三样一次填好，确认后生成一张补录单（QC 开头）。再打开时会带出已经补录过的，可以接着改。
- **买的套餐还剩多少**：
  - 选水品和自提 / 配送，再选当时买的套餐。套餐价和张数会自动带出，可以改成当时实际付的。
  - 填现在还剩几桶 / 袋，弹窗显示按原价折合多少钱。
  - 不记得买的什么套餐，就选「套餐不清楚」，只记张数。
- **押金和手里的桶袋**：每种桶袋填上系统前交的押金个数、每个多少钱，以及现在手里几个。没交过押金就不用填。手里比押金多时，弹窗提示下次领桶会让补交押金。
- **不算今天收的钱**：这些钱当时已经收过，只是没进系统。
  - 补录的套餐不算水费实收，也不进趋势。
  - 补录的押金在池里、能退，但不算「累计收押」；押金管理另外注明“另有上系统前已收 N 笔 ¥X”。
  - 经营总览「可能要退给会员的钱」照样算上：知道套餐的，剩下的按当时实付折算进没用完的水费；套餐不清楚的只列张数。
- **先用先退**：会员下单先用上系统前剩下的，退押金先退上系统前交的那笔。知道套餐的余量能按当时实付原价退清，套餐不清楚的不能按原价退。
- **录错了能改**：
  - 还剩数量可以改，但不能少于未完成水单占着的，也不能多于套餐张数。
  - 没下过单、没退过款的余量可以删掉。
  - 押金没退过、没报废扣过时可以改个数和单价，改成 0 就是删掉。
  - 手里的个数随时可改。
  - 已经退款或有退款在审核的不能改，要退请走退款。系统里充值的批次不能在这里改。
- **都有记录**：每次补录或修改都留一张补录单，写明谁、什么时候、改了什么（如“原来 40 → 35”）和备注。会员档案的「上系统前的数据」卡片、押金管理、袋桶台账、会员最近记录都以「上系统前」标出。

验收：
- 给老会员补录“桶装水自提 499 元 / 95 桶，还剩 40 桶”、押金 2 个 × 50 元、手里 2 个桶后：
  - 档案显示可用水票 40、手里 2 个桶、已交押金 ¥100、没用完的水费 ¥210.11；
  - 水费实收和累计收押不变，在池押金加 ¥100，对账仍一致；
  - 袋桶台账出现“上系统前 · 补录原来就在会员手里的 · 0 → 2 个”。
- 把还剩改成 35 后，没用完的水费变为 ¥183.84；退清这笔余额，正好退 ¥183.84。
- 店员调用补录接口返回无权限；同一次补录重复提交只记一次。

## 35. 赠送一律审核、交付写清桶还是袋、费用支出（2026-11-17）

正式环境开始使用后客户提出三个问题。本节为准，替代第 30 节中“管理员自己充值赠送总是直接生效”。

- **赠送一律要管理员批准**：门店收银用的是唯一的管理员账号，之前管理员账号填的赠送当场到账，审核页里什么也看不到（2026-11-17 晚正式库 3 笔赠送都是这样到账的，已到账的不追溯）。现在「手动赠送要审核」开关打开时，不管谁填的赠送都先记为待审核，付费水票照常当场到账；管理员在「审核」页批准后赠送才到账，同一个管理员可以批准自己填的。开关名改为「手动赠送要审核」。退押金、退水费不变：管理员自己办理直接生效。
- **交付写清桶还是袋**：确认交付（配送、自提核销）原来不管什么水都写“满桶领出 / 空桶收回”，送 5L 袋装水时押金却按水袋算，看起来像“送的是桶、押的是袋”。现在交付弹窗顶部写明这单的水品和配套容器（如“5L 袋装水 · 配套水袋”，押金 ¥5/个，会员手里几个、押金覆盖几个），数量写“满袋领出 / 空袋收回”或“满桶领出 / 空桶收回”；收回的空桶（袋）多于会员名下的，提示多出的按会员自带的换给店里、不收押金，不是自带的请改回。押金核对没完成或失败时不能提交，免得没算押金就交付。水单详情、点单结算的押金提示和后台补押金提示同样按桶 / 袋说。
- **费用支出**：「财务管理」新增「费用支出」，记水站平时花出去的钱：
  - 类别：买桶袋、配件耗材（桶盖、压水器、饮水机配件、滤芯等）、维修、其他；填买了什么、数量、一共花了多少钱（精确到分）、付款方式、购买日期（默认今天，可补登以前的，不能晚于今天）、备注。单号 `ZCyyyyMMddNNNN`。
  - 登记错了不删除：写明原因作废，作废的还在列表里（变灰、金额划掉），不计入任何合计。
  - 袋桶库存「新购」时可以顺手填花了多少钱和付款方式，同时记一笔「买桶袋」支出，库存记录和支出互带单号；供应商送的空着不填。作废这笔支出不改库存。
  - 统计：费用支出页上方四个数跟着所选时间（默认本月）——费用支出合计和笔数、买桶袋及其他各类合计、同期水费净收（实收 − 退款）、结余（水费净收 − 费用支出）。经营总览新增「本月收支」卡片。押金是会员的钱，不算收入也不算支出。可按单号 / 买了什么 / 备注 / 经办人搜索，按类别、有效 / 已作废、购买日期筛选，导出支出明细。
  - 权限：登记、作废需新权限「登记费用支出」（`kunlun.waterstation:expense:manage`），管理员自动拥有；查看还可用报表权限。店员、送水员暂不开放；手机端「袋桶库存」新购不显示花费。

验收：管理员账号充值 100 元 50 袋并赠送 1 袋，会员当场有 50 袋，审核页出现“充值赠送 1 袋”，批准后变成 51 袋。会员手里 4 个水袋时配送 6 袋，交付弹窗写“5L 袋装水 · 配套水袋”“满袋领出 6 / 空袋收回 4”，需补 2 个水袋的押金 ¥10。登记一笔配件耗材“压水器” 2 个 ¥36.50 后，费用支出页本月支出增加 ¥36.50、结余减少同样的数；作废后回落。袋桶库存新购 10 个桶并填花费 ¥280，店里加 10 个，费用支出出现“买桶袋 · 15L 桶装水 · 配套桶 × 10 · ¥280”，再点一次同一请求不会重复记。
