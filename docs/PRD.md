## 1. 背景与目标

水站需要统一管理会员、充值赠水、押金、自提配送及桶袋流转，解决水费、水票、押金和容器数量混合记账导致的对账困难，并保证三端业务数据一致。

### 1.1 产品目标

1. 建立完整会员档案，集中查询充值、赠水、用水、押金及桶袋领还记录。
2. 水费、水票、押金、桶袋数量独立记账，所有变动可追溯。
3. 支持自提与配送差异化充值方案，桶装水与袋装水分别管理。
4. 打通下单、预占、履约、核销及取消释放的完整水单流程。
5. 准确反映站内库存、配送在途、会员持有及可退押金额度。
6. 通过权限控制、操作留痕、幂等及关联纠错降低误操作风险。

### 1.2 成功指标

以下指标用于上线后的业务验收与运营观察，具体目标值在试运行后确定：

- 水单、充值、押金、容器记录均可关联到会员、单号、时间和操作人。
- 水票不存在透支，重复提交不产生重复入账。
- 任一会员的押金余额、容器持有量及可退额度可核对。
- 管理端汇总与业务明细口径一致，可导出对账。
- 三端查询同一业务时状态与数量一致。

## 4. 核心概念与数据口径

### 4.1 水品与领取方式

- 水品：桶装水、袋装水。
- 领取方式：自提、配送。
- 水票按“水品 + 领取方式”分账，首期形成四类水票：自提桶票、配送桶票、自提袋票、配送袋票。
- 不同类别默认不互换，不合并展示为可随意使用的统一余额。

### 4.2 四类独立账目

| 账目 | 单位 | 典型变动 |
| --- | --- | --- |
| 水费账 | 元 | 充值实收、经授权的关联纠错 |
| 水票账 | 桶或袋 | 充值购水、赠水、下单预占、交付扣减、取消释放 |
| 押金账 | 元及押金数量 | 交押金、补交、退款、关联纠错 |
| 容器账 | 个 | 领出、归还、在途、持有变动 |

规则：押金不参与充值赠水；交押金不等于领走容器；归还容器不等于已退押金。

### 4.3 水票口径

对每一类水票分别记录：

- 累计到账：购买到账与赠送到账之和。
- 可用数量：当前可用于新下单的数量。
- 预占数量：已下单但尚未完成或取消的数量。
- 已使用数量：已完成履约并核销的数量。

约束：

- `可用数量 >= 0`，`预占数量 >= 0`，`已使用数量 >= 0`。
- 下单时增加预占并等额减少可用。
- 完成时减少预占并增加已使用，不重复扣减。
- 取消时减少预占并等额恢复可用。
- 购买数量与赠送数量须分别留存，赠水扣减顺序待确认。

### 4.4 押金与容器口径

桶和袋分别记录：

- 已交押金数量及押金金额。
- 会员实际持有容器数量。
- 履约预占的新增容器占用数量。
- 当前可退押金数量及金额。

可退押金数量按以下原则计算：

`可退数量 = max(0, 未被实际持有或履约新增占用覆盖的已交押金数量)`

退款金额按原押金收款记录的实际单价计算，不使用修改后的当前单价。具体退款批次选择规则见第 16 章待确认项。

### 4.5 容器数量口径

管理端至少分别展示桶、袋的：

- 容器总量。
- 站内可用数量。
- 配送在途数量。
- 会员实际持有数量。
- 回收待检数量（如启用该状态）。
- 异常数量及异常明细。

库存台账和会员持有台账可以按单据联动，但须保留独立流水，不能只保存汇总值。

1. 工作台：班次、个人业绩、待办水单和快捷入口。

### 5.3 会员端小程序

1. 首页：水票摘要、配送/自提入口、进行中水单、押金与容器摘要。
2. 水单：进行中、已完成、已取消及详情。

## 6. 会员管理需求

### 6.1 会员字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 会员编号 | 系统生成 | 全站唯一，创建后不可修改 |
| 姓名 | 是 | 去除首尾空格，长度及字符规则由设计统一 |
| 联系电话 | 是 | 用于查询及账号识别，重复处理规则待确认 |
| 收货地址 | 配送时必填 | 可保存多个，每个含收货地址（小区/街道/楼栋）、门牌号、联系人、手机号；联系人和手机号默认带出会员本人，可改为代收人；其中一个为默认地址 |
| 会员状态 | 系统生成 | 正常、停用；停用是否限制下单待确认 |
| 备注 | 否 | 员工或管理员填写 |
| 创建时间/来源 | 系统生成 | 会员注册、员工新建或历史导入 |

### 6.2 查询与新建

- 支持按姓名、电话、会员编号查询。
- 员工办理业务前必须选定唯一会员。
- 未找到会员时可进入新建流程，新建成功后返回原业务。
- 姓名、电话未通过校验时不得保存。
- 配送地址可在下单时补充，非配送会员允许暂不填写。

### 6.3 会员 360° 详情

至少展示：

- 基础资料、状态和会员编号。
- 四类水票的可用、预占及已使用数量。
- 桶、袋押金数量与金额。
- 实际持有桶袋和可退押金额度。
- 充值、赠水、用水、押金、容器领还及纠错记录。
- 快捷入口：充值、押金、代开水单、登记领还。

## 7. 充值与优惠需求

### 7.1 优惠方案字段

| 字段 | 说明 |
| --- | --- |
| 方案名称 | 便于员工识别，如“桶装水配送畅享包” |
| 充值金额 | 本方案应收水费，不包含押金 |
| 适用水品 | 桶装水或袋装水，可关联具体规格 |
| 领取方式 | 自提或配送 |
| 购买数量 | 按金额购得的水票数量 |
| 赠送数量 | 额外赠送的水票数量 |
| 状态 | 启用、停用 |
| 生效时间 | 建议保留，具体是否支持定时生效应在评审时确认 |
| 创建/修改信息 | 操作人和时间 |

同样金额允许因自提/配送不同而配置不同购买及赠送数量。

### 7.2 水费充值流程

1. 员工选择或新建会员。
2. 系统展示当前可用优惠方案。
3. 员工选择方案，系统展示水品、领取方式、购买数量、赠送数量、到账总数及实收金额。
4. 员工选择收款方式并确认实际已收款。
5. 服务端校验方案状态、会员状态和请求唯一性。
6. 在同一事务中保存充值单、水费实收、购水及赠水水票流水。
7. 返回充值结果和最新水票余额。

### 7.3 充值快照

每笔充值必须保存：

- 原方案 ID 和方案名称。
- 当时的充值金额、水品、领取方式、购买数量和赠送数量。
- 实际收款金额及收款方式。
- 会员、操作人、时间和业务单号。

后续修改或停用方案不得改变历史充值记录。

### 7.4 充值异常

- 重复点击或网络重试不得重复收款、重复赠水。
- 任一子账写入失败时整笔充值失败，不允许只增加水票但未保存实收。
- 充值错误通过关联原充值单的纠错记录处理；是否允许水费退款及其规则待确认。

## 8. 押金管理需求

### 8.1 独立入口

员工端提供独立的“交押金/押金充值”入口，支持：

- 首次预交押金。
- 新增领用前补交押金。
- 押金退款前的额度核对。
- 押金退款登记。
- 查询押金流水和关联容器记录。

不得将押金金额混入水费充值金额，也不得触发赠水。

### 8.2 交押金流程

1. 选择会员。
2. 选择桶或袋及数量。
3. 系统按当前押金单价试算应收金额。
4. 员工确认实际收款并登记收款方式。
5. 系统增加对应押金数量和金额，保存单价及收款快照。
6. 容器持有数量不因交押金而变化。

### 8.3 新增领用与补交

- 已交押金覆盖的容器正常等量换水，不重复收押金。
- 当本次新增领用导致押金覆盖不足时，系统提示需补交的容器数量及金额。
- 未补足时是否允许继续履约由第 16 章规则决定；原型按“不足需补交”设计。
- 实际领出、收回空容器和押金收款分别生成流水，并通过会员及水单关联。

### 8.4 退押金流程

1. 员工选择会员和容器类型。
2. 系统展示已交押金、实际持有、履约新增占用及可退额度。
3. 如先归还容器，先登记实际归还数量并更新持有台账。
4. 系统按原押金收款金额计算可退金额。
5. 员工复核后确认退款，保存实际退款金额、方式、操作人和时间。
6. 退押金不自动修改会员实际持有数量。

无可退额度时不得提交成功，并展示占用原因及关联水单/容器记录。

## 9. 水单与履约需求

### 9.1 下单字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 水单号 | 系统生成 | 全局唯一 |
| 会员 | 是 | 会员下单自动带入本人 |
| 下单来源 | 系统生成 | 会员下单或员工代开 |
| 领取方式 | 是 | 自提或配送 |
| 水品及规格 | 是 | 桶装水或袋装水 |
| 下单数量 | 是 | 正整数，不能超过对应可用水票 |
| 配送地址 | 配送必填 | 默认带入会员默认收货地址，可选择其他地址或当场新增；下单后保存为本单快照 |
| 期望时间 | 否 | 营业时段及配送规则待确认 |
| 备注 | 否 | 会员或员工填写 |
| 操作人 | 系统生成 | 会员本人或代开员工 |

### 9.2 水单状态

| 状态 | 适用 | 说明 |
| --- | --- | --- |
| 待接单 | 配送 | 已创建并预占水票，等待员工接单 |
| 待自提 | 自提 | 已创建并预占水票，等待到店交付 |
| 配送中 | 配送 | 员工已接单，可记录在途容器 |
| 已完成 | 全部 | 已确认实际交付，水票及容器完成核销 |
| 已取消 | 全部 | 水单关闭，预占水票已释放 |
| 异常 | 全部，可选 | 履约存在差异或异常，需人工处理；具体规则待确认 |

状态必须按允许路径变化，不能直接删除历史水单。

### 9.3 配送主流程

会员下单或员工代开 → 校验并预占水票 → 员工接单 → 配送中 → 确认实际交付 → 扣减预占水票 → 登记容器领出和收回 → 完成并留痕。

### 9.4 自提主流程

会员下单或员工代开 → 校验并预占水票 → 生成待自提水单 → 员工核对会员 → 确认实际交付 → 扣减预占水票 → 登记容器领出和收回 → 完成并留痕。

### 9.5 确认交付

交付页至少包含：

- 原水单号、会员、领取方式、水品和下单数量。
- 实际交付水量。
- 实际新增领出容器数。
- 收回空容器数。
- 押金覆盖校验结果。
- 交付时间、操作人及必要备注。

等量换水示例：交付 2 桶、收回空桶 2 个、新增领出 0 个，会员持有数量不变，不重复收押金。

实际交付与下单不一致时，不得简单覆盖原单数量；应保存原下单数量、实际交付数量及差异原因，并同步调整预占。超出原预占部分须重新校验可用水票，不足时不得透支。

### 9.6 取消规则

- 取消成功后释放全部未履约预占水票及容器新增占用。
- 已交付或已完成部分不能直接通过整单取消冲回，应走关联纠错流程。
- 可取消状态、取消角色、接单后是否允许取消及原因必填规则待确认。

## 12. 设置需求

### 12.1 优惠方案

支持新建、编辑、启用和停用方案；历史充值保留快照。

### 12.2 押金与容器

- 桶、袋分别设置押金单价。

- 权限至少覆盖会员、充值、押金、退款、水单、容器、报表和设置。

- 支持自动备份策略、最近备份时间和结果展示。

- 备份数据访问权限与全站管理权限一致。

## 13. 通用业务规则

1. 水费、水票、押金、容器数量分别记账。
2. 水票按水品和领取方式分别管理，默认不互换。
3. 下单预占、完成核销、取消释放；任何环节不得出现负可用水票。
4. 押金不参与充值赠水，押金金额不进入水费实收。
5. 等量换水不重复收押金，新增领用须校验押金覆盖。
6. 只有未被实际持有或履约新增占用的押金可退，按原收取金额退款。
7. 所有业务保留唯一单号、创建时间、操作人及必要的关联单号。
8. 提交、网络重试及重复消息必须执行幂等校验。
9. 已完成业务不得物理删除或直接篡改，通过关联原单的纠错记录处理。
10. 汇总值与流水必须可对账；流水和汇总更新须保证事务一致性。
11. 三端共享同一数据源，不以各端本地数据作为最终账目。
12. 金额使用定点小数计算，禁止浮点误差进入账务结果。

## 14. 非功能需求

### 14.1 安全

- 三端真实登录，密码等敏感凭据不得明文保存。
- 所有业务接口执行身份、角色和数据权限校验。
- 会员只能访问本人资料和业务记录。
- 关键操作记录登录账号、操作人、时间、对象和结果。
- 导出、退款、设置及纠错等高风险操作需防重复提交并保留审计记录。
- 具体会话时长、登录失败锁定和二次验证策略由安全设计确定。

### 14.2 易用性

- 员工端和会员端优先适配常见手机屏幕，核心按钮易于单手点击。
- 充值、交押金、代开水单等高频入口置于员工工作台。
- 数量、金额、单位及水票类别必须同时清晰展示。
- 失败提示说明原因和可执行的下一步，不能只提示“操作失败”。
- 加载期间防止重复提交；成功后展示单号及关键结果。

### 14.3 性能与可用性

- 常规查询和页面操作在正常网络下应有及时反馈，具体响应指标由技术评审确定。
- 账务写入必须具备事务和并发控制，避免并发下单造成超扣。
- 数据定期备份，并进行恢复可用性验证。
- 浏览器兼容范围在研发评审时明确。

### 14.4 日志与审计

日志至少包括登录、会员资料变更、充值、押金收退、水单状态变化、容器领还、方案设置、权限设置、导出和纠错。业务日志不可被普通员工删除。

## 18. 已确认变更：固定套餐、赠水券与原价退款（2026-10-26）

本节取代前文充值赠送、赠票扣减顺序和水费退款待确认条款。沿用现有三端 HTML 页面实现真实接口和数据库事务，不重新设计页面。

| 领取方式 | 实收金额 | 固定付费水票 |
| --- | ---: | ---: |
| 自提 | 100 元 | 16 桶 |
| 自提 | 500 元 | 95 桶 |
| 配送 | 100 元 | 13 桶 |
| 配送 | 500 元 | 70 桶 |

- 管理员可新增、修改、停用套餐；金额、水品、领取方式和数量只影响新充值。每笔充值保存完整快照，不追溯改写已到账权益。
- 每笔充值形成独立水票批次，按水品和领取方式隔离。先充先分配，同批次先付费后赠送。下单预占到具体批次，取消原路释放；核销按实交付数量结算，数量差异需理由。
- 管理员配置充值赠水券，授权员工发放。配置指定套餐、赠票数、可兑换起止时间、每人领取次数和启停状态。一笔充值最多核销一张本人优惠券；发券次数与已用次数不会因退款恢复。已发券保存规则及适用套餐条件快照；套餐金额、固定数量、水品或领取方式变化后，原券不能套用变更后的套餐。停用券模板只停止后续发券。
- 券须在有效期内兑换；兑换后的赠票不单设有效期、不折现。赠票与付费票分开记录，未完成的付费票订单不能被赠票订单绕过后全额退款。
- 管理员可按充值批次退清剩余权益。退款金额 = 原实付金额 × 剩余付费票数 ÷ 原固定票数，使用 decimal，最终金额四舍五入到分。原批次剩余赠票全部收回，已使用券不恢复。存在预占的批次先完成或取消水单。
- 充值与退款为线下收付款登记，不自动执行微信、支付宝或银行转账。押金与桶袋持有独立核算。退款留存原批次、退付费数量、收回赠票数量、金额、方式、原因和操作人。
- 幂等标识配合事务、行锁保证重复点击、网络重试和并发请求不重复入账；跨会员或不同业务内容复用标识会被拒绝。
- 既有余额按历史批次保留，未知购买/赠送来源不会猜测重算；可继续使用，自动退款需先有可靠原单来源。既有未完成水单的预占同时迁入批次。

验收示例：自提充值 100 元到账 16 张付费票，优惠券赠 1 张；核销 6 张后剩余付费 10、赠票 1，退清时退款 62.50 元并收回赠票。会员可在本人账户查看充值批次、退款状态和优惠券，不能访问其他会员权益。

## 24. 周转水袋与库存维护（2026-10-26）

用户确认：袋子不是一次性耗材，按可回收周转容器管理，水袋新收押金为 5 元/个。旧押金批次与会员押金余额不改写，退款仍按原收款单价计算；标准迁移只执行一次，不覆盖后续人工修改。

桶袋台账增加管理员库存维护：

| 操作 | 处理规则 |
| --- | --- |
| 采购入库 | 可用库存和现存总量同时增加 |
| 破损登记 | 从可用、在途、待检、异常或会员归还转入破损待处理，现存总量不变 |
| 修复入库 | 破损减少，可用增加，现存总量不变 |
| 确认报废 | 从破损扣减，减少现存总量，累计报废增加 |
| 库存盘点 | 对选定库存位置按实盘差额调整并留痕；提交时验证原账面数量，变化则要求重新盘点 |

会员持有数量不允许直接盘点覆盖，应通过领还或会员破损归还处理。会员破损归还须选择会员并确认实物已收回，在同一事务内减少会员持有、增加破损并记录关联流水。所有库存操作均不自动退押、扣赔偿或变更水票。

现存总量 = 可用 + 在途 + 会员持有 + 待检 + 异常 + 破损；累计报废不计入现存总量。所有数量非负，报废/修复/报损不允许超量。操作保存原因、操作人、时间、前后数量、请求标识和关联会员，可按桶/袋查询并导出。默认仅管理员拥有库存维护权限；行锁和幂等键保证重复请求、并发操作不重复入账。
